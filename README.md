# Severity-Aware 2-Type MSDA: Fair Task Offloading for IoT-Fog Healthcare Systems

A severity-aware task offloading algorithm for IoT-Fog healthcare networks that extends the [M-DAFTO](https://doi.org/10.1109/JIOT.2022.3183979) framework with **two-type task classification**, **energy-aware urgency scoring**, and **type-separated multi-stage deferred acceptance matching** to significantly reduce outage probability for critical healthcare operations.

---

## 📌 Problem Statement

In smart healthcare IoT systems, computational tasks (surgery scheduling, patient monitoring, diagnostic imaging) generated by IoT devices must be offloaded to nearby **Fog Nodes** (edge servers) for real-time processing. The challenge is:

- **Tasks have strict deadlines** — a surgery task must be processed within seconds.
- **Fog Nodes have limited capacity** (CPU, VRUs) — not every task can be assigned.
- **Not all tasks are equal** — a Major surgery is far more critical than a routine checkup.
- **An unassigned task = an OUTAGE** — in healthcare, outages on critical tasks are unacceptable.

The existing M-DAFTO algorithm treats all tasks identically in a single pool, causing **critical Major tasks to compete equally with routine Minor tasks**, leading to avoidable outages on high-priority operations.

---

## 💡 Proposed Solution

We redesign the matching algorithm as a **2-Type Multi-Stage Deferred Acceptance (MSDA)** system:

| Aspect | Baseline (M-DAFTO) | Proposed (2-Type MSDA) |
|:---|:---|:---|
| Task Classification | None — single pool | **Major** (critical) vs **Minor** (routine) |
| Urgency Criteria | 2 (Delay, Preference Count) | **4** (Delay, Preference Count, **Energy**, **Severity**) |
| AHP Matrix | 2×2 (always consistent) | **4×4** with consistency check (CR ≤ 0.1) |
| Quota System | Single min/max per fog node | **Separate quotas** for Major and Minor tasks |
| Normalization | Delay only | Delay + Energy, with **severity-weighted** scaling |
| Matching | Single-Type DA | **2-Type DA** with three-constraint rejection |

### Key Contributions

1. **2-Type MSDA Algorithm** — Separate quota tracking and preference lists for Major (R-type) and Minor (S-type) tasks within the same multi-stage deferred acceptance framework, with a Modified DA that simultaneously enforces Major quota, Minor quota, and total capacity constraints.

2. **Energy-Aware Urgency Function** — Extended the urgency formula from 2 to 4 criteria, incorporating energy consumption and a severity multiplier (γ = 1.5 for Major, 1.0 for Minor).

3. **Severity-Weighted Normalization** — Minor tasks receive a 0.5 weight reduction on normalized metrics, enabling differentiated fog node preference ordering.

4. **Greedy Placement Baseline** — Added a third comparison algorithm (GPM) as a lower-bound benchmark.

- Results averaged over 10 iterations per scenario to account for randomness

## 📁 Codebase Structure

### Orchestrator
| File | Description |
|:---|:---|
| **`Main.java`** | Entry point — orchestrates the full pipeline across 4 scenarios (250–2000 tasks) with 10 iterations each. Runs independent pipelines for Baseline, Proposed, and GPM algorithms. |
| **`MSDAlgorithm.java`** | Core matching logic — implements `matchBaseline` (Single-Type MSDA), `match` (2-Type MSDA), and `matchGPM` (Greedy Placement). Contains the Modified DA with three-constraint rejection. |

### Data Models
| File | Description |
|:---|:---|
| **`SimulationConfig.java`** | Central configuration — all constants (CPU ranges, deadlines, VRU bounds, fog node count). |
| **`Task.java`** | Task data model — holds per-fog-node arrays for delay, energy, normalized values, urgencies, and preferences. Includes severity (`Major`/`Minor`) and phase (`Pre-Surgery`/`Post-Surgery`). |
| **`FogNetwork.java`** | Fog node data model — CPU capacity, VRU count, derived VRU capacity, and separate quota fields for all-tasks and major-tasks. |
| **`SimulationData.java`** | DTO aggregating all computed arrays (tasks, fog nodes, normalized metrics, preference lists, precedence lists, weights). |

### Computation Pipeline
| File | Description |
|:---|:---|
| **`TaskGenerator.java`** | Generates randomized IoT tasks with CPU demand, data sizes, deadlines, phase, and severity. |
| **`FogNetworkGenerator.java`** | Generates randomized fog nodes with CPU capacity and VRU count. |
| **`OffloadingCalculator.java`** | Computes transmission time, execution time, receiving time, total delay, and energy for every task×fog pair. |
| **`Normalizer.java`** | Global Min-Max normalization with severity-weighted scaling (Minor tasks get 0.5 weight reduction). |
| **`WeightGenerator.java`** | AHP weight generation — 4×4 pairwise comparison matrix with consistency check (CR ≤ 0.1). |
| **`UrgencyCalculator.java`** | Multi-criteria urgency computation using 4 AHP-weighted criteria. |
| **`QuotaDeterminator.java`** | Proportional quota computation based on VRU capacity relative to the most efficient fog node. |
| **`PreferenceRanker.java`** | Generates fog-side preference rankings (All/Major/Minor) and deadline-sorted precedence lists. |

### Output
| File | Description |
|:---|:---|
| **`SimulationPrinter.java`** | Complete output layer — matching results, per-FN statistics, utilization bars, satisfaction metrics, fairness indexes (Gini, Jain). |
| **`SimulationMetrics.java`** | Accumulator for averaging metrics across iterations (delay, energy, outage, satisfaction). |

## ⚙️ Mathematical Model

### 1. Delay & Energy Calculations
For each task $T_i$ on Fog node $F_j$:

$$D_{ij} = \underbrace{\frac{\text{Input Size}}{\text{Uplink Rate}}}_{T_{\text{tx}}} + \underbrace{\frac{\text{CPU Demanded}}{\text{VRU Capacity}}}_{T_{\text{exec}}} + \underbrace{\frac{\text{Output Size}}{\text{Downlink Rate}}}_{T_{\text{rx}}}$$

$$E_{ij} = P_{\text{tx}} \cdot T_{\text{tx}} + P_{\text{exec}} \cdot T_{\text{exec}} + P_{\text{rx}} \cdot T_{\text{rx}}$$

### 2. Task Urgency (Extended from M-DAFTO)

**Baseline (M-DAFTO)** — 2 criteria:
$$U_{ij}^{\text{base}} = w_1 \cdot \frac{1}{\text{Deadline} - D_{ij}} + w_2 \cdot \frac{1}{\text{pref}(T_i)}$$

**Proposed (2-Type MSDA)** — 4 criteria:
$$U_{ij}^{\text{prop}} = w_1 \cdot \frac{1}{\text{Deadline} - D_{ij}} + w_2 \cdot \frac{1}{\text{pref}(T_i)} + w_3 \cdot \frac{1}{E_{ij}} + w_4 \cdot \gamma_i$$

Where:
- $w_1, w_2, w_3, w_4$ are AHP-generated weights (consistency ratio CR ≤ 0.1)
- $\text{pref}(T_i)$ = number of fog nodes that can complete $T_i$ before its deadline
- $\gamma_i$ = severity score: **1.5** for Major, **1.0** for Minor tasks

### 3. AHP Weight Generation
- **Algorithm 4 (PMC)**: Generates 4×4 pairwise comparison matrix using Saaty's scale
- **Algorithm 5 (CWD)**: Column normalization → row averaging → weight vector
- **Algorithm 6 (CC)**: Consistency check — $CR = \frac{\lambda_{\max} - n}{(n-1) \cdot RI} \leq 0.1$

### 4. Quota Determination
Each fog node $F_j$ gets proportional minimum quotas:
$$l(F_j) = \min\left(h(F_j),\ \left\lfloor \frac{\lambda_j}{\lambda_{\max}} \cdot l_{\max} \right\rfloor\right)$$

Where $\lambda_j$ = VRU capacity, $\lambda_{\max}$ = capacity of the most efficient node, $l_{\max} = \min(h_{\max}, \lfloor |T|/|F| \rfloor)$

## 🛠️ How to Compile & Run

> **Prerequisites**: Java SE Development Kit (JDK) 8 or later.

### Compile
```bash
javac *.java
```

### Run
```bash
java Main > output.txt
```

> **Windows PowerShell** (if encoding issues): `java Main | Out-File -Encoding utf8 output.txt`

### Output
The program produces:
- **Scenario Summaries** — Averaged metrics (outage, delay, energy, satisfaction) across 10 iterations for each of the 4 task scales (250, 500, 1000, 2000)
- **Detailed Results** — Per-iteration breakdown with matching tables, per-FN delay/energy, resource utilization bars, traffic load, Gini and Jain fairness indexes
