  SECTION 2:  YOUR ACTUAL TECHNICAL CONTRIBUTIONS (What You Changed)
================================================================================

You made the following changes/extensions to the base M-DAFTO paper:

  1. TWO-TYPE TASK CLASSIFICATION (New Concept)
     ─────────────────────────────────────────────
     - M-DAFTO treats all tasks identically (single-pool matching).
     - You introduced a "severity" field: Major (critical/high-risk operations
       like major surgeries) vs Minor (routine tasks like checkups).
     - Major tasks get separate minimum quotas (pr_c), maximum quotas (qr_c),
       and a separate preference ranking on each fog node.
     - This ensures critical healthcare operations are NEVER starved of resources.

  2. TWO-TYPE MSDA MATCHING ALGORITHM (Core Algorithm Extension)
     ─────────────────────────────────────────────────────────────
     - M-DAFTO uses a Single-Type MSDA (Algorithm 2 in their paper) which treats
       all tasks in one undifferentiated pool.
     - You designed a 2-Type MSDA that maintains separate quota tracking for
       Major (R-type) and Minor (S-type) tasks WITHIN the same multi-stage
       deferred acceptance framework.
     - Your algorithm runs a "Modified DA" (runModifiedDA) which simultaneously
       enforces:  qr_c (max Major quota), q_c - pr_c (max Minor quota), and
       q_c (total capacity) — a three-constraint rejection mechanism.
     - In the final stage, your algorithm handles three cases:
       (a) Exact R-type count → DA for R-types + Single-Type MSDA for S-types
       (b) Exact S-type count → DA for S-types + Single-Type MSDA for R-types
       (c) Otherwise → Recursive 2-Type MSDA
     - This prevents the "Major task starvation" that happens in M-DAFTO's
       single-pool approach.

  3. ENERGY CONSUMPTION AS A METRIC (New Dimension)
     ────────────────────────────────────────────────
     - M-DAFTO's urgency function uses only 2 criteria:
       U = w1 * 1/(Deadline-Delay) + w2 * 1/pref(Ti)
     - You extended it to 4 criteria:
       U = w1 * 1/(Deadline-Delay) + w2 * 1/pref(Ti) + w3 * 1/Energy + w4 * γ(Ti)
     - Energy is computed as: (TxPower × TxTime) + (ExecPower × ExecTime) + (RxPower × RxTime)
     - This makes the urgency score energy-aware, favoring assignments that
       minimize both delay AND power consumption.

  4. SEVERITY SCORE IN URGENCY (γ Factor)
     ──────────────────────────────────────
     - You added a severity multiplier γ(Ti) to the urgency formula.
     - γ = 1.5 for Major tasks (c=1, α=0.5 → 1 + 1×0.5)
     - γ = 1.0 for Minor tasks
     - This naturally pushes Major tasks higher in fog node preference lists.

  5. SEVERITY-WEIGHTED NORMALIZATION
     ────────────────────────────────
     - M-DAFTO uses plain Min-Max normalization on delay.
     - You apply severity-based weight reduction: Minor tasks get 0.5 weight
       on their normalized delay and energy values.
     - This means Minor tasks generate lower normSum values, leading to
       different fog node preference orders compared to Major tasks.

  6. 4×4 AHP INSTEAD OF 2×2
     ───────────────────────
     - M-DAFTO uses a 2×2 AHP matrix (always consistent by definition).
     - You use a 4×4 AHP matrix with full consistency checking (CR ≤ 0.1),
       supporting the 4-criteria urgency function.

  7. SEPARATE MAJOR/MINOR PREFERENCE LISTS & PRECEDENCE LISTS
     ──────────────────────────────────────────────────────────
     - You generate separate fog-side preference rankings for Major-only
       and Minor-only tasks (rankMajorTasksPerFog, rankMinorTasksPerFog).
     - You build separate deadline-sorted precedence lists for each type.
     - These feed into the 2-Type MSDA so each type is handled with its
       own priority ordering.

  8. GREEDY PLACEMENT METHOD (GPM) AS ADDITIONAL BASELINE
     ─────────────────────────────────────────────────────
     - You added a third comparison algorithm (GPM) that simply assigns tasks
       greedily to fog nodes sorted by capacity, with no fairness or urgency
       consideration.
     - This provides a lower-bound comparison point.

  SECTION 7:  DOMAIN CONTEXT (Healthcare Fog Computing — for your reference)
================================================================================

  What is the domain problem?
  ───────────────────────────
  In a smart hospital or healthcare IoT setup:
  - IoT devices (monitors, sensors, medical equipment) generate computational
    TASKS (e.g., processing surgery data, patient monitoring, imaging).
  - These tasks need to be processed by nearby FOG NODES (edge servers in the
    hospital network) rather than sending everything to the distant cloud.
  - Each fog node has limited resources (CPU, VRUs = Virtual Resource Units).
  - Tasks have DEADLINES — a surgery task must be processed within X seconds.
  - If a task can't be assigned to any fog node before its deadline → OUTAGE.
  - In healthcare, outages for Major operations (surgeries) are unacceptable.

  How does matching work?
  ───────────────────────
  - Each TASK has a preference list of fog nodes (ranked by least delay+energy).
  - Each FOG NODE has a preference list of tasks (ranked by urgency score).
  - The MSDA algorithm runs Deferred Acceptance in multiple stages, where
    lower-priority tasks get deferred to later stages to make room for
    higher-priority ones in the current stage.
  - Quotas ensure minimum fairness — every fog node must accept at least
    some tasks, proportional to its capacity.

  SECTION 8:  COMMON INTERVIEW QUESTIONS & ANSWERS
================================================================================

Q: "What is the time complexity of your algorithm?"
A: "Each DA round is O(T × F) where T = tasks and F = fog nodes. The number
   of stages in MSDA is bounded by T (each stage removes at least one task).
   So worst case is O(T² × F). In practice, it converges much faster because
   the quota constraints limit the number of stages."

Q: "Why Deferred Acceptance and not other algorithms?"
A: "DA guarantees stability — no task-fog pair would both prefer each other
   over their current match. This is critical in healthcare where you can't
   have a situation where a surgery gets assigned to a weak node while a
   better node is underutilized. Also, MSDA specifically handles minimum
   quotas (fairness) which basic DA cannot."

Q: "How did you validate your results?"
A: "Each scenario was run 10 times with different random seeds to average
   out variance. I compared three algorithms (Greedy, Baseline M-DAFTO,
   and my 2-Type MSDA) across 4 scales (250, 500, 1000, 2000 tasks).
   Metrics include outage rate, average delay, total energy, task/FN
   satisfaction (Eq. 20-22 from the paper), and Gini/Jain fairness indexes."

Q: "What would you improve if you had more time?"
A: "Three things: (1) Add dynamic task arrival instead of batch processing,
   (2) Implement task migration — reassigning tasks when fog node loads
   change, and (3) Test with real-world healthcare workload traces instead
   of synthetic data."

Q: "What design patterns did you use?"
A: "The codebase follows a clean modular pipeline architecture. Each stage
   of the computation (generation, calculation, normalization, ranking,
   matching, output) is a separate class with a clear responsibility.
   The SimulationData DTO pattern aggregates all computed arrays for
   easy passing between pipeline stages. Deep copy is used to ensure
   independent algorithm pipelines don't contaminate each other's state."

Q: "How is this different from just load balancing?"
A: "Standard load balancing optimizes for throughput or latency alone.
   This is a MULTI-CRITERIA MATCHING problem that simultaneously
   optimizes for: deadline compliance, energy efficiency, resource
   fairness across fog nodes, AND severity-based prioritization.
   It's also not a greedy assignment — it uses game-theoretic stable
   matching to find globally optimal assignments."
