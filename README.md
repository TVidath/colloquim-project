# 2-Type MSDA: Fair Task Offloading in IoT-Fog Systems

This repository contains a comprehensive Java-based simulation environment designed to evaluate a **Proposed 2-Type Multi-Stage Deferred Acceptance (MSDA)** algorithm for fair task offloading in IoT-Fog networks. It also includes an exact implementation of the **Baseline M-DAFTO MSDA** algorithm for direct, side-by-side performance comparison.

---

## 🚀 Overview

In IoT-Fog computing architectures, tasks generated by IoT devices must be offloaded to appropriate Fog nodes. The allocation must balance delay, energy consumption, urgency, resource fairness, and the differing severity of tasks (e.g., Major vs. Minor).

This simulation framework:
1. **Generates Simulation Configurations**: Deploys a set of Fog networks with distinct capacities and generates high-frequency computational tasks with varying deadlines, phases, and severity levels (Major/Minor).
2. **Computes Offloading Metrics**: Calculates transmission delay, execution delay, receiving delay, and total energy consumed per task across all Fog nodes.
3. **Normalizes Metrics Globally**: Applies Min-Max normalization to delay and energy parameters.
4. **Calculates Urgency Values (AHP)**: Employs multi-objective weight parameters to compute the urgency of each task relative to each Fog node, effectively prioritizing critical tasks.
5. **Generates Preference Rankings**: Ranks tasks based on urgency for each Fog node.
6. **Executes Matching Algorithms**: 
   - **Baseline M-DAFTO**: A single-type MSDA algorithm that relies heavily on strict quotas.
   - **Proposed 2-Type MSDA**: A two-type task classification algorithm that treats Major and Minor tasks differently to maximize deadline compliance and resource efficiency.

## ⚙️ Mathematical Model

### 1. Delay & Energy Calculations
For each task $T_i$ on Fog node $F_j$:
* **Transmission Time**: $T_{\text{tx}} = \frac{\text{Input Size}}{\text{Uplink Data Rate}}$
* **Execution Time**: $T_{\text{exec}} = \frac{\text{CPU Demanded}}{\text{VRU Capacity}}$
* **Receiving Time**: $T_{\text{rx}} = \frac{\text{Output Size}}{\text{Downlink Data Rate}}$
* **Offloading Delay**: $D_{ij} = T_{\text{tx}} + T_{\text{exec}} + T_{\text{rx}}$
* **Energy**: $E_{ij} = (P_{\text{tx}} \times T_{\text{tx}}) + (P_{\text{exec}} \times T_{\text{exec}}) + (P_{\text{rx}} \times T_{\text{rx}})$

### 2. Task Urgency
The urgency $U_{ij}$ of task $T_i$ for Fog node $F_j$ is calculated as:
$$U_{ij} = w_1 \cdot \frac{1}{\text{Deadline} - D_{ij}} + w_2 \cdot \frac{1}{\text{pref}(T_i)} + w_3 \cdot \frac{1}{E_{ij}} + w_4 \cdot \gamma_i$$
Where:
* $w_1, w_2, w_3, w_4$ are AHP-generated weights.
* $\text{pref}(T_i)$ is the number of Fog nodes that can complete $T_i$ before its deadline.
* $\gamma_i$ is the severity score ($1.5$ for Major, $1.0$ for Minor tasks).

## 🛠️ How to Compile & Run

> [!NOTE]
> Ensure you have the Java SE Development Kit (JDK) 8 or later installed.

### 1. Compile
Compile all source files from the repository root:
```bash
javac *.java
```

### 2. Run
Execute the simulation. To easily compare the Baseline vs. Proposed algorithm results, it is highly recommended to redirect the output to a text file:
```bash
java Main > output.txt
```

*(If you are using Windows PowerShell and encounter encoding issues when viewing the text file, use this command instead: `java Main | Out-File -Encoding utf8 output.txt`)*

---

## 📊 Output Description
When run, the simulation outputs to the console (or `output.txt`):
* **Simulation Configuration**: Details of tasks and generated Fog node metadata.
* **AHP Diagnostics**: Weight generation diagnostics with mathematical consistency checks.
* **Pre-Processing Outputs**: Priority lists, minimum/maximum quotas, and deadline-sorted precedence lists.
* **Baseline M-DAFTO Results**: Detailed matching metrics (Outage rate, average delay, energy consumption, fairness indexes) for the Single-Type algorithm.
* **Proposed 2-Type MSDA Results**: Detailed matching metrics for the 2-Type algorithm, clearly showcasing differences in major/minor task handling and overall satisfaction relative to the baseline.
