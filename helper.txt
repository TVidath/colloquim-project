================================================================================
  PROJECT HELPER: FILE CONTENTS & RESPONSIBILITIES
================================================================================

This document provides a high-level overview of what each file in the project does. 

--------------------------------------------------------------------------------
1. CORE SIMULATION & DATA STRUCTURES
--------------------------------------------------------------------------------
- Main.java
  The entry point of the application. It orchestrates the entire simulation, 
  looping through different scenarios (e.g., 250, 500, 1000, 2000 tasks) and 
  running 10 iterations per scenario to average out results.

- SimulationConfig.java
  Holds all the hardcoded constants, parameters, and settings for the simulation 
  (e.g., minimum/maximum data sizes, CPU cycles, deadlines, AHP matrix bounds).

- Task.java
  The data model representing an IoT task. Stores attributes like data size, 
  CPU cycles required, deadline, severity ("Major" or "Minor"), and maintains 
  lists for calculated delays, energies, and preferences.

- FogNetwork.java
  The data model representing a Fog Node (FN). Stores attributes like CPU 
  frequency, transmission rate, number of VRUs, and quota limits.

- SimulationData.java
  A convenient wrapper object that holds all generated entities (Tasks, FNs) 
  and computed matrices (delays, preferences) so they can be easily passed 
  between different components of the simulation.

--------------------------------------------------------------------------------
2. GENERATORS & CALCULATORS
--------------------------------------------------------------------------------
- TaskGenerator.java
  Generates the random lists of IoT tasks based on the bounds set in SimulationConfig.

- FogNetworkGenerator.java
  Generates the random lists of Fog Nodes based on the bounds set in SimulationConfig.

- OffloadingCalculator.java
  Calculates the raw physics of the simulation: offloading delay (communication + 
  computation) and energy consumption for assigning a specific task to a specific FN.

- Normalizer.java
  Applies min-max scaling to the raw delays and energies so that they can be 
  combined into a single urgency score evenly. It also applies the penalty 
  weights based on task severity (Major vs Minor).

- UrgencyCalculator.java
  Calculates the "urgency score" for each task, which determines how badly a 
  task needs a specific Fog Node.

- QuotaDeterminator.java
  Calculates the Minimum Quota (MinQ) and Maximum Quota (MaxQ) for each Fog Node, 
  determining how many tasks they are willing to accept.

--------------------------------------------------------------------------------
3. RANKING & MATCHING (THE ALGORITHM)
--------------------------------------------------------------------------------
- WeightGenerator.java
  Implements the Analytic Hierarchy Process (AHP). It generates a random comparison 
  matrix, calculates the Consistency Ratio (CR), and derives the final weights 
  (w1, w2, w3, w4) used for scoring.

- PreferenceRanker.java
  Creates the preference lists. It ranks FNs from the perspective of each Task, 
  and ranks Tasks from the perspective of each FN. 

- MSDAlgorithm.java
  The core matching logic. It implements the Multi-Stage Deferred Acceptance (MSDA) 
  algorithms. It runs both the Baseline algorithm (Single-pool matching with 
  relaxation) and our Proposed algorithm (2-Type Major/Minor MSDA matching).

--------------------------------------------------------------------------------
4. METRICS & OUTPUT
--------------------------------------------------------------------------------
- SimulationMetrics.java
  A data class used to accumulate performance metrics (delays, energy, outages, 
  satisfaction) across multiple iterations and calculate their averages.

- SimulationPrinter.java
  Handles all the terminal output formatting. It generates the detailed per-iteration 
  tables, the Major/Minor breakdowns, and the final Scenario Summary tables.

- output.txt
  The actual output log generated by running the simulation.

- project_flow.txt (and .md)
  The comprehensive step-by-step documentation detailing the exact mathematical 
  logic and sequence of operations performed by the code.
